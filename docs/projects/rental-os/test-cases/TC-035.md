## Preconditions

Authorized staging session; disposable test records; record the deployed build and test account role. The original live UI did not expose an independently verified deployed SHA.

## Procedure

1. Provision authorized disposable companies A and B with distinct customers and rentals; create A-operator, B-operator and A-viewer accounts. Record the permission policy.
2. As A-operator, request B customer/rental IDs through normal detail URLs and the matching authenticated API calls; repeat in reverse as B-operator.
3. As A-viewer, attempt booking creation, invoice/payment mutation and document modification. Check persisted state using the corresponding authorized operator.
4. Sign out each session and remove or suspend the disposable accounts through the approved cleanup workflow.

## Expected result

Cross-company objects are denied or hidden with no record fields disclosed. Viewer mutations are denied by the server and produce no stored change. Exact 403/404 behavior follows the approved API policy. Historical live testing had only one company/account: this multi-role case remains unexecuted.

## Recorded observation

Only one authenticated account/company available

## Limits and cleanup
