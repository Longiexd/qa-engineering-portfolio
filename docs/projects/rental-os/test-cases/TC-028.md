## Preconditions

Authorized staging session; disposable test records; record the deployed build and test account role. The original live UI did not expose an independently verified deployed SHA.

## Procedure

1. In disposable staging prepare two separate rentals, A and B, each with a correctly configured, collected 500 TND deposit and verified pickup documents. Record invoice, journal and payment IDs.
2. Complete actual pickup and return for A, record mileage 12,500 km, complete the three inspection checks and save approval. Reopen the booking, verify stored mileage/inspection and process the approved 500 TND refund.
3. For B, record damage with note QA bumper damage and retain 100 TND using the configured damage settlement; refund the other 400 TND. Reopen both records and inspect posted ledger entries and reconciliations.
4. Repeat each completed settlement action once only in the disposable harness; compare settlement IDs and balances. Record reversal/cleanup ownership.

## Expected result

A: refunded 500, retained 0, held 0 TND. B: refunded 400, retained 100, held 0 TND; only the retained amount becomes damage income under the approved accounting policy. Saved mileage/notes persist; a duplicate attempt creates no second settlement. Historical execution was not completed: this remains a planned integration case, not a pass.

## Recorded observation

No existing return was changed; QA booking has not passed pickup/document gates

## Limits and cleanup

Reconstructed procedure, not a verbatim historical script. This case has not been rerun for the portfolio. Preserve original records and avoid repeating payment actions when the first result is uncertain. Arrange reversal/cancellation of new synthetic records through the authorized staging workflow and record what remains.
