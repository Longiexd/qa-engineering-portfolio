# TC-014 — Repeat deposit invoice action

| Field | Value |

| Priority | P1 |

## Preconditions

Authorized staging session; disposable test records; record the deployed build and test account role. The original live UI did not expose an independently verified deployed SHA.

## Procedure

1. Create the 500 TND deposit-only draft and note its invoice ID.
2. Repeat the same deposit invoice action once and inspect all linked invoices.

## Expected result

The same draft ID is reused; exactly one deposit draft exists. This checks sequential duplication, not simultaneous requests.

## Recorded observation

One existing draft reused; no second invoice shown

## Limits and cleanup

Reconstructed procedure, not a verbatim historical script. This case has not been rerun for the portfolio. Preserve original records and avoid repeating payment actions when the first result is uncertain. Arrange reversal/cancellation of new synthetic records through the authorized staging workflow and record what remains.
