# QA-01 — Calendar overstates availability

**State:** Historical finding; current fix status not verified
**Environment:** Authenticated staging
**Observed:** 28 October 2026
**Evidence:** E01; original screenshot retained privately
**Classification:** Functional defect; P2


Reproduction: open Vehicles, Fleet Care, and Calendar in the same company/session. Vehicles and Fleet Care show 6 available, 3 unavailable, and 1 cleaning, out of 10. Calendar shows 9 available and 1 cleaning. Analytics agrees with the 6-available count.

Impact: staff get conflicting operational availability information, including vehicles blocked by required evidence.

Source corroboration: `frontend/app/dashboard/calendar/page.tsx:314` uses a separate status classifier, including substring checks for `disponible` and `available`, instead of the operational eligibility result. This also risks classifying `indisponible`/`unavailable` as available. Use the existing authoritative eligibility/state mapping across Calendar and Fleet, with a regression covering blocked vehicles and negative state names.

Evidence: `calendar-availability-mismatch.png`; live Fleet/Fleet Care accessibility observations.
